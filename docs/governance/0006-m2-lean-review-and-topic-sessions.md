# Governance record 0006 — M2 lean review and topic sessions

Date: 2026-08-03

Authority: Live (arbiter)

## Ruling

Live approved the M2 interaction correction in full. A review round now means
one Executor Proposal, independent parallel Audits of that frozen proposal, and
one automatic Executor Synthesis. The Synthesis is the proposal reviewed by the
next round. An Auditor failure pauses before Synthesis until Live chooses retry
or explicit continuation without that audit.

The participant model expands from a hard-coded pair to exactly one Executor
and an ordered set of one or more Auditors. Every active participant must come
from a distinct vendor. This is an architectural expansion, not permission to
display or invoke a provider whose real adapter, first-party subscription gate,
and capability evidence do not exist.

Dialektikḗ topics become the canonical owner-local conversation. Topics own
their configuration and ordered cycles, support rename/pin/archive operations,
and use append-only deletion tombstones while immutable run evidence remains.
Follow-up context contains prior Live messages and prior Executor Syntheses; old
Audits remain displayed and saved but are not repeatedly sent to models.

The approved desktop layout and behavior are recorded in `DIRECTIVE.md`: Live
on the workspace centreline, Executor and Auditors centred in their respective
halves, full-half response lanes, bottom composer, provider-native selectors,
real progress only, inert high-fidelity response rendering, and native-faithful
permission cards retaining only Allow once and Deny.

## Consequence

The earlier M2 implementation that stopped after an Auditor, used in-memory
topic fixtures, displayed a preview-only Gemini seat, and exposed inert sidebar
controls is incomplete against this ruling. The correction continues M2; it is
not a new milestone or a weakening of any M1 axiom.
